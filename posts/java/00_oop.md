## 2. 클래스와 객체

클래스를 설명할 때 흔히 `붕어빵 틀` 과 `붕어빵` 비유... 난 그렇게 좋아하지 않는다. 함께 SF 세계관으로 들어가보자!  

클래스는 고도의 기능을 갖춘 **로봇의 설계도**라고 할 수 있다. 설계도에는 로봇에 필요한 부품(`속성`)과 작동 방식(`메서드`)이 상세히 기록되어 있다.  

이 세계관의 모든 로봇이 공통적으로 가져야 할 스펙을 정의한 `Robot` 클래스를 가정해 보자. 로봇은 체력(hp)이 0이 되면 파괴되고 기술을 사용하려면 에너지(mp)를 소모하며, 고유한 이동 속도(speed)를 가진다. 정말 친숙한 개념이며, Java 코드로 아래와 같이 표현할 수 있다.  

``` java
public class Robot {
    int hp;
    int mp;
    int speed;
}

```

이 설계도는 로봇이 가져야 할 데이터 형식을 정의할 뿐, 그 자체로 움직이는 실체는 아니다.  
설계도에 기반하여 실제 공장에서 찍어낸 로봇을 바로 **객체(Object)** 또는 **인스턴스(Instance)** 라고 부르는 것이다!  

굳이굳이 이러한 일련의 관리 수단으로 클래스를 사용하는 이유는 관리의 효율성 때문이다.  
로봇 A, B, C를 만들 때마다 매번 사양을 처음부터 작성하는 것은 비효율적이며, 로봇의 종류가 늘어날수록 유지보수가 불가능해진다. 공통적인 속성을 클래스로 묶어 관리하면 설계도의 수정만으로 모든 로봇의 기본 규격을 일괄적으로 제어할 수 있다.

## 3. 생성자

생성자는 클래스 구조를 메모리의 **힙(Heap) 영역** 에 할당하여 실체화된 객체로 만들 때 호출되는 특수한 메서드이다. 즉, 로봇 설계도를 바탕으로 실제 로봇을 생산하는 `출고 버튼 `과 같은 역할을 한다. 우린 생성자를 통해 객체 생성 규칙을 정의하고 초기 상태를 마구마구 설정할 수 있다.  

<br>

### 3-1. 기본 생성자

개발자가 클래스 내부에 생성자를 하나도 작성하지 않으면, 자바 컴파일러가 아무런 매개변수가 없는 기본 생성자를 자동으로 추가한다.
이는 별도의 커스텀 설정 없이 그저 공장에서 기본 사양으로 로봇을 출고하는 버튼이 생긴 것과 같다.

``` java
class Robot {
    int hp;
    int mp;
    int speed;
}

public class Main {
    public static void main(String[] args) {
        // 컴파일러가 자동으로 제공한 기본 생성자 호출
        Robot robot = new Robot(); 
    }
}

```

<br>

### 3-2. 매개변수가 있는 생성자

로봇을 생산하는 시점에 특정 옵션(hp, mp, speed)을 직접 지정하고 싶을 때 사용한다. 이는 생성과 동시에 멤버 변수를 초기화하는 효율적인 방법이다.

```java
class Robot {
    int hp;
    int mp;
    int speed;

    Robot(int hp, int mp, int speed) {
        this.hp = hp; // this는 생성된 객체 자신을 가리킴
        this.mp = mp;
        this.speed = speed;
    }
}

```

주의할 점은 개발자가 매개변수가 있는 생성자를 직접 정의하는 순간, 자바 컴파일러는 더 이상 기본 생성자를 자동으로 제공하지 않는다는 것이다. 이는 **데이터 무결성**을 지키기 위함이다! 로봇 생산 시 필수 데이터가 누락된 채로 출고되는 상황을 방지하기 위해, 개발자가 의도한 생성 방식만을 강제하는 효과가 있다. 만약 기본 생성자도 함께 사용하고 싶다면 아래와 같이 명시적으로 선언해야 한다.

```java
class Robot {
    int hp; int mp; int speed;

    Robot() {} // 명시적으로 선언해야 사용 가능

    Robot(int hp, int mp, int speed) {
        this.hp = hp;
        this.mp = mp;
        this.speed = speed;
    }
}

```

### 3-3. 생성자 오버로딩 (Overloading)

모두 알다시피 오버로딩은 이름은 같지만 매개변수의 구성이 다른 여러 생성자를 두는 것을 의미한다.
이를 통해 상황에 맞는 다양한 공정으로 로봇을 생산할 수 있다. 예를 들어, 기본 속도가 10으로 고정된 일반 모델과, 속도까지 커스텀 가능한 강화 모델을 선택적으로 생산하는 방식이다. _어느날 갑자기 기존 로봇보다 3배 빠른 로봇을 만들어야할 수도 있기 때문이다..._

```java
class Robot {
    int hp; int mp; int speed;

    // 일반 모델: 속도가 10으로 고정됨
    Robot(int hp, int mp) {
        this.hp = hp;
        this.mp = mp;
        this.speed = 10;
    }

    // 커스텀 모델: 모든 사양 지정 가능
    Robot(int hp, int mp, int speed) {
        this.hp = hp;
        this.mp = mp;
        this.speed = speed;
    }
}
```
