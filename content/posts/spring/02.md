## 비즈니스 요구정리
- 데이터: 회원Id, 이름
- 기능: 회원등록, 조회
- 아직 데이터 저장소가 선정되지 않음.

도메인
- 객체
- User 와 같은 데이터를 담는 가장 기본 단위
- DB에 저장될 항목들을 정의 (회원, 상품, 주문 등)

레포지토리
- 도메인 객체를 저장하고 관리하는 저장소
- c++으로 치면 std::map<int, User*> users 에 접근하여 find(), insert()를 수행
- 즉, DB에 접근하여 데이터를 저장, 수정, 삭제, 조회하는 일을 전담.

서비스
- 비즈니스 로직을 수행하는 계층
- "회원 가입을 할떄, 중복 아이디가 있는지 확인한다" 같은 실제 정책을 코드로 구현
- 레포지토리와 컨트롤러 사이의 핵심다리이며, 서비스는 레포지토리를 활용하여 데이터를 가져오고 가공한다.

컨트롤러
- http 요청의 진입점
- url 매핑을 통해 외부의 요청을 받고, 서비스에 일을 시킨 뒤, 그 결과를 모델에 담아 화면에 보여주거나 Json으로 반환









## 자바 람다 함수
``` text
// 기본형
(매개변수) -> { 실행문; }

// 매개변수가 2개인 경우
(a, b) -> { return a + b; }

// 매개변수가 1개인 경우 (괄호 생략 가능)


// 실행문이 한줄인 경우 (중괄호와 return 생략 가능)
(a, b) -> a + b
```



``` java
@Override
public Optional<Member> findByName(String name) {
    // 1. 데이터를 흐르게 하고
    return store.values().stream()
            // 2. 조건에 맞는 것만 걸러내서
            .filter(member -> member.getName().equals(name)) 
            // 3. filter를 통과한 데이터 중에서 가장 먼저 발견된 하나를 반환한다.
            .findAny();
}
```

`member -> member.getName().equals(name)`
- `member` : "벨트 위를 지나가는 회원 한 명을 member라고 부를게."
- `->` : "이 회원을 가지고 다음 계산을 해봐."
- `member.getName().equals(name)` : "이 회원의 이름이 파라미터로 받은 name과 같은지 비교해봐! (결과는 true 아님 false로 나올 거야)"
- `filter` : "방금 계산 결과가 true인 회원만 남기고 나머지는 다 걸러버릴게!"
