## 1. 소개

이 디지털 객체지향 세상에서 캡슐화란 무엇일까?
흔히들 캡슐화란 관련된 데이터와 기능을 하나의 클래스에 담고, 내부의 복잡한 내용은 감추는 것을 의미한다.
캡슐화를 통해 아래 두가지 이득을 얻을 수 있다.

- 정보 은닉
    - 객체 내부의 데이터(필드)가 외부에서 마음대로 수정되지 않도록 보호하는 기능
- 결합도 낮추기
    - 객체 내부의 구현 방식이 바뀌더라도, 그 객체를 사용하는 외부 코드는 영향을 받지 않게 하는 것입니다.

..? 정말 하나도 와닿지 않는다. 이게 도대체 무슨 소리일까..? 이번에도 어김없이 로봇과 함께 `뉴 네오 서울 2030` 객체지향의 세계로 모험을 떠나보자! 렛츠고!


## 2. 캡슐화

이전에 우리는 로봇 설계도를 만들었고, 로봇을 생산하는 버튼도 만들었음. (생성자)
그런데 생성자 버튼을 쓰다보면 우리가 약속한 hp, mp, speed 에 다양한 값을 넣어 다양한 상태의 로봇을 만들 수 있음.
hp100, Mp10, speed10 도 가능할것이고, hp20, mp10, speed30도 가능할것.
그렇다면... hp-100, mp-21474836000, speed 2147483648 인 로봇도 가능할까?

구현이, 그러니까 법적으로 금지된 것은 아니다. 그렇지만 `뉴 네오 서울 2030` 의 관리자로써 당신은 저런 로봇이 존재하는 것을 참을 수 있는가..?
적어도 `뉴 네오 서울 2030` 세상에서는 저런 로봇의 구현은 존재할 수 없으며 이러한 존재의 탄생은 당신이 막아야한다. 당신은 관리자니깐.
즉, 로봇 생산과정에서 당신은 로봇 배선과 회로를 다 꺼내놓고 생산할 것인가의 문제이다.

``` java
// 누군가(사용자)가 마음대로 내부를 건드리는 상황
// 뉴 네오 서울의 관리자인 당신이 막아야만 한다...
Robot badRobot = new Robot();
badRobot.hp = -500;
badRobot.speed = 9999;
```

- 정보 은닉
    - 객체 내부의 데이터(필드)가 외부에서 마음대로 수정되지 않도록 보호하는 기능

이제 `정보 은닉` 의 필요성이 느껴지기 시작한다. 현실세계에서는 이것이 은행잔고의 접근, 실제 공장 로봇의 관절 가동 범위 등등에서 적용될 것이다.
사용자에게는 편리한 스위치만 주고, 로봇의 내부 동작이 담겨있는 로직은 숨기고 또 숨겨야 이런 상황을 막을 수 있다.  

지금 우리의 `Robot`은 모든 부품이 밖으로 드러난, 언제든지 hp = -999가 될 수 있는 상태이다. 그럼 어떻게 막을 수 있을지 알아보자.

## 2-1. getter/setter

우선 우리의 목표는 아무나 Robot.hp = -500; 이런 접근을 하지 못하게 막는 것. 즉, 우리 로봇 내부에 접근해서 특정 값을 보거나 세팅할때 우리가 미리 설정한 제어가 들어가있는 창구를 이용하게끔 따로 버튼을 만들어 주는 것. 이때 조회하는 버튼이 getter, 값을 넣는 버튼이 setter이다. 이 버튼 동작과정에서 각각의 값을 안전하게 조회하고 안전하게 바꿀 수 있게할 수 있음.

``` java
class Robot {
    int hp;
    int mp;
    int speed;
    
    // 생성자 생략 ...

    // getter
    int getHp() {
        return this.hp;
    }
    
    int getMp() {
        return this.mp;
    }
    
    int getSpeed() {
        return this.speed;
    }

    // setter

    

}
```

## 2-1. 접근제어자

가장 먼저 할 일은 외부에서 로봇의 내부 수치(`hp`, `mp`, `speed`)를 직접 건드리지 못하게 접근 제어자를 사용하는 것이다.  

접근 제어자를 사용하여 변수나 메서드의 사용 권한을 설정할 수 있으며, `private < default < protected < public` 순으로 보다 많은 접근을 허용한다.

- `private`
    - 해당 클래스 내부에서만 접근 가능
- `default`
    - 접근 지정자를 지정하지 않았을 경우 설정되며, 패키지 내부에서만 접근 가능
- `protected`
    - 동일 패키지 클래스 또는 해당 클래스를 상속 받은 클래스에서만 접근 가능
- `public`
    - 어디서든 접근 가능

지금은 `private` 와 `public` 에만 집중하자. 밖으로 드러나있는 맴버 변수를 `private` 로 설정하여 외부에서 이상한 사용자들이 참견할 수 없도록 막아버릴 것이다.

```java
class Robot {
    // 외부 노출 차단 (private)
    private int hp;
    private int mp;
    private int speed;

    Robot () {}

    Robot(int hp, int mp, int speed) {
        this.hp = hp;
        this.mp = mp;
        this.speed = speed;
    }
}
```

이제 누군가 외부에서 `robot1.hp = -100;` 이런식으로 접근하면 컴파일 에러가 날 것이다. 즉 private 접근 제어자를 통해 robot. 식의 외부 접근을 막아버린것. 정비사가 로봇 배선을 직접 만지는 사고를 막은 것.

### 2. 단계: 불량 부품 거르기 (데이터 검증)

캡슐화를 하면 `Setter` 메서드 내부에서 데이터를 검사할 수 있습니다. 2026년형 로봇이라면 당연히 **안전 시스템**이 있어야겠죠?

```java
class Robot {
    private int hp;
    // ... 생략

    public void setHp(int hp) {
        if (hp < 0) {
            System.out.println("안전 시스템: 체력은 0 미만이 될 수 없습니다. 0으로 고정합니다.");
            this.hp = 0;
        } else {
            this.hp = hp;
        }
    }
}

```

* **강의 포인트:** "사용자가 실수로 이상한 값을 넣어도, 로봇 클래스가 스스로를 보호합니다. 객체의 **무결성**을 지키는 핵심입니다."

---

### 3. 단계: 복잡한 로직 숨기기 (추상화와 캡슐화)

사용자(Main)는 로봇의 수치를 직접 계산할 필요가 없습니다. 로봇에게 **명령**만 내리면 됩니다.

```java
class Robot {
    private int hp;
    private int mp;

    // "마나 10을 써서 체력 20을 회복해"라는 복잡한 로직을 메서드 안에 감춥니다.
    public void selfRepair() {
        if (this.mp >= 10) {
            this.mp -= 10;
            this.hp += 20;
            System.out.println("수리 완료! 현재 HP: " + this.hp);
        } else {
            System.out.println("에너지가 부족하여 수리할 수 없습니다.");
        }
    }
}

```

* **강의 포인트:** "`Main` 클래스에서 일일이 계산기를 두드리지 마세요. 로봇에게 '수리해!'라고 말하면, 로봇이 알아서 마나를 깎고 체력을 올립니다. 이것이 **객체에 메시지를 던지는 방식**입니다."

---

### 4. 단계: 최종 진화 (읽기 전용과 읽기/쓰기 분리)

어떤 데이터는 태어날 때 정해지면 절대 바뀌면 안 됩니다. 캡슐화는 이를 완벽하게 제어합니다.

```java
class Robot {
    private final String serialNumber; // 시리얼 번호는 변경 불가
    private int hp;

    Robot(String sn, int hp) {
        this.serialNumber = sn;
        this.hp = hp;
    }

    // 시리얼 번호는 읽기(Getter)만 가능하고 수정(Setter)은 아예 만들지 않습니다.
    public String getSerialNumber() {
        return serialNumber;
    }
}

```

### 💡 요약: 캡슐화 전 vs 후 비교

| 구분 | 초기 코드 (Open) | 캡슐화 코드 (Protected) |
| --- | --- | --- |
| **데이터 접근** | `robot.hp = -5;` (직접 수정) | `robot.setHp(-5);` (검증 후 수정) |
| **사고 발생** | 말도 안 되는 데이터가 들어감 | 객체가 스스로 에러를 방어함 |
| **로직 위치** | `Main`에서 로직을 구현함 | `Robot` 내부에서 로직을 처리함 |
| **보안/안전** | 로봇 속이 훤히 들여다보임 | 필요한 버튼(메서드)만 노출됨 |

> **"캡슐화는 로봇의 부품을 함부로 만지지 못하게 상자에 넣고, 밖에는 안전한 조작 버튼만 달아두는 것과 같습니다."**
